Camera Stream Options

Choose how to handle RTSP camera streams. Pick one to implement.

EASIEST

Snapshot Polling

How it works: Capture a frame from RTSP every N seconds, serve as JPEG.

Pros:

  • Simple to implement
  • Works in any browser
  • Low bandwidth
  • No transcoding server needed

Cons:

  • Not real-time (1-5 second delay)
  • Choppy "slideshow" effect

Requirements:

pip install opencv-python

Implementation:

import cv2

def capture_snapshot(rtsp_url):
    cap = cv2.VideoCapture(rtsp_url)
    ret, frame = cap.read()
    cap.release()
    if ret:
        _, jpeg = cv2.imencode('.jpg', frame)
        return jpeg.tobytes()
    return None

# Flask route
@app.route('/camera/<id>/snapshot')
def snapshot(id):
    img = capture_snapshot(cameras[id]['rtsp_url'])
    return Response(img, mimetype='image/jpeg')

Frontend: Just use <img> with refresh interval

setInterval(() => img.src = '/camera/1/snapshot?' + Date.now(), 2000)
MEDIUM

MJPEG Transcoding

How it works: ffmpeg converts RTSP to Motion JPEG stream.

Pros:

  • Real-time streaming
  • Native browser support (<img> tag)
  • No JavaScript needed for playback

Cons:

  • Higher bandwidth than H.264
  • Requires ffmpeg running
  • One ffmpeg process per camera

Requirements:

apt install ffmpeg

Implementation:

import subprocess

def generate_mjpeg(rtsp_url):
    cmd = [
        'ffmpeg', '-i', rtsp_url,
        '-f', 'mjpeg',
        '-q:v', '5',
        '-r', '10',  # 10 fps
        'pipe:1'
    ]
    proc = subprocess.Popen(cmd, stdout=subprocess.PIPE)
    while True:
        chunk = proc.stdout.read(4096)
        if not chunk:
            break
        yield chunk

@app.route('/camera/<id>/stream')
def stream(id):
    return Response(
        generate_mjpeg(cameras[id]['rtsp_url']),
        mimetype='multipart/x-mixed-replace; boundary=frame'
    )

Frontend:

<img src="/camera/1/stream">
ADVANCED

WebRTC Gateway

How it works: Full WebRTC stack for real-time video.

Pros:

  • True real-time (<500ms latency)
  • Efficient H.264 passthrough
  • Two-way audio possible
  • Adaptive bitrate

Cons:

  • Complex setup
  • Requires STUN/TURN servers
  • More infrastructure

Options:

  • go2rtc - Easiest WebRTC gateway
  • mediamtx - Full-featured media server
  • Janus - WebRTC server (complex)

go2rtc setup:

# docker-compose.yml
services:
  go2rtc:
    image: alexxit/go2rtc
    ports:
      - "1984:1984"   # API
      - "8555:8555"   # WebRTC
    volumes:
      - ./go2rtc.yaml:/config/go2rtc.yaml

# go2rtc.yaml
streams:
  cam1: rtsp://user:pass@192.168.1.100:554/stream
  cam2: rtsp://user:pass@192.168.1.101:554/stream
